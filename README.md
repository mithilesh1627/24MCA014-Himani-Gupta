# Student Success Prediction & Early-Warning System

**MCA Final-Year Project | Synthetic 200,000-student dataset | Python + scikit-learn**

An end-to-end machine-learning project that predicts a student's final academic score and estimates whether the student may be academically at risk. It demonstrates the full ML lifecycle: synthetic data generation, EDA-ready tabular data, preprocessing, feature engineering, baseline models, advanced ensemble models, hyperparameter tuning, model fusion, evaluation, inference, and held-out-institution domain generalization.

> **Data ethics:** all records are synthetic and generated by this repository. They are not real student records and must not be presented as collected institutional data. The model is an academic prototype, not a tool for making consequential decisions about students.

## 1. Project objectives

- Generate 200,000 reproducible synthetic student records.
- Predict `final_score` (regression).
- Predict `at_risk` (classification; score below 60 in the synthetic generator).
- Compare interpretable baselines with nonlinear models.
- Engineer interaction and engagement features.
- Tune a Random Forest using `RandomizedSearchCV`.
- Fuse models with voting and stacking.
- Test generalization on institutions withheld from training.
- Save reusable models and machine-readable evaluation reports.

## 2. Dataset

The generator creates academic, engagement, and contextual features such as attendance, study hours, previous GPA, internal marks, assignment completion, LMS logins, missed deadlines, commute time, internet access, and program. Institution-specific shifts are deliberately introduced to create a domain-generalization experiment.

Targets:
- `final_score`: continuous score from 0 to 100.
- `at_risk`: 1 when synthetic final score is below 60; otherwise 0.

The target is generated from a nonlinear formula with noise and interactions. This makes the dataset useful for demonstrating modelling techniques, but performance on it is not evidence of real-world educational validity.

## 6. Models and techniques

### Regression
- Linear Regression: simple baseline.
- Ridge Regression: regularized linear baseline.
- Decision Tree: nonlinear single-tree model.
- Random Forest: bagged decision trees.
- Extra Trees: randomized tree ensemble.
- HistGradientBoosting: boosting model for tabular data.
- Tuned Random Forest: RandomizedSearchCV over tree count, depth, leaf size, and feature sampling.
- Voting Regressor: prediction-level fusion of diverse models.
- Stacking Regressor: a Ridge meta-model learns from out-of-fold base-model predictions.

### Classification
- Logistic Regression baseline.
- Decision Tree, Random Forest, Extra Trees, HistGradientBoosting.
- Soft Voting and Stacking ensembles.
- Metrics: accuracy, precision, recall, F1, ROC-AUC.

### Feature engineering
- Study-hours × attendance interaction.
- Average assessment performance.
- Deadline rate normalized by semester.
- LMS engagement per study hour.
- Commute burden and sleep deviation.

### Hybrid early-warning technique
The inference script blends the classifier probability with a score-derived risk signal: `0.7 × classifier risk + 0.3 × (1 − predicted score / 100)`. This is a transparent demonstration heuristic, not a statistically calibrated probability. The threshold can be validated and tuned on a real validation set in future work.

### Domain generalization experiment
Institutions 0–7 are source domains. Institutions 8–9 are held out entirely for evaluation. Institution ID is removed from the input features. This tests whether relationships learned in source institutions transfer to unseen synthetic institutions. It is a stress test, not a guarantee of real-world domain robustness.

## 8. Evaluation and limitations

- Regression: MAE, RMSE, R².
- Classification: precision, recall, F1, ROC-AUC.
- Domain generalization: MAE, RMSE, R² on held-out institutions.
- A high score on synthetic data is expected because the target is created from the supplied features. It does not establish that the model will predict real student outcomes accurately.
- Do not use the prototype to deny opportunities, assign grades, or label real students without consent, validation, human oversight, and institutional review.
- A next research step is to evaluate on a consented, anonymized, institutionally approved real dataset and compare calibration and subgroup error.

## Viva quick answers

**Why synthetic data?** To make a reproducible, privacy-safe prototype when approved institutional data is not available. It is clearly labelled synthetic.

**Why both regression and classification?** Regression estimates a continuous score; classification converts the outcome into an early-warning signal.

**What is fusion?** Combining multiple models. Voting averages model outputs; stacking trains a meta-model to combine base-model predictions.

**What is domain generalization?** Evaluating whether a model trained on some environments/institutions works on an unseen environment.

**How do you avoid leakage?** Student ID and target columns are excluded from model inputs. Preprocessing is fitted within the training pipeline.

**What is the biggest limitation?** Synthetic data cannot prove real-world validity. A future phase requires consented real data and independent external validation.
